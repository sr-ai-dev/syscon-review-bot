# 대형 PR 분할 리뷰 및 비용 제어 요구사항

## 배경

현재 리뷰봇은 PR 전체를 한 번의 리뷰 입력으로 처리한다. 변경량이 크면 핵심 파일이 압축 과정에서 제외되고, 교차 파일 검증 정확도가 떨어질 수 있다. 병렬 리뷰를 도입하더라도 사용자에게 여러 리뷰가 게시되면 결과를 읽고 판정하기 어렵다. 또한 모델 호출, 도구 반복, 재시도, 최종 통합에 공통 비용 상한이 없어 PR 하나가 예상보다 큰 비용을 만들 수 있다.

## 요구사항

- PR이 자동 리뷰 허용 상한 이내인 경우, 시스템은 내부 실행 방식과 관계없이 GitHub 리뷰를 정확히 한 번 시도해야 한다.
- PR이 단일 리뷰 기준을 초과하고 자동 리뷰 허용 상한 이내인 경우, 시스템은 변경 파일을 내부 shard로 나누어 병렬 검토해야 한다.
- 내부 shard 검토가 완료된 경우, 시스템은 결과를 하나의 `ReviewResult`로 통합한 뒤 기존 리뷰 형식으로 한 번만 게시해야 한다.
- 내부 reviewer는 GitHub 리뷰 또는 코멘트를 직접 게시할 수 없어야 한다.
- PR이 가중 변경량 2,500줄, 유효 파일 80개, 또는 raw diff 100,000 tokens 중 하나를 초과한 경우, 시스템은 LLM 리뷰를 실행하지 않고 PR 분리 안내를 한 번 게시해야 한다.
- 필수 변경 파일의 patch를 가져오지 못하거나 shard에 포함하지 못한 경우, 시스템은 불완전한 결과를 승인으로 게시하지 않아야 한다.
- 비용 제어가 활성화된 경우, 시스템은 모든 reviewer, 도구 반복, 재시도, judge, 통합 호출에 하나의 PR 비용 원장을 공유해야 한다.
- 첫 OpenAI 요청 전에, 시스템은 계획된 전체 실행 비용의 보수적 상한을 계산해야 한다.
- 예상 비용이 신뢰된 PR별 비용 상한을 초과한 경우, 시스템은 OpenAI 요청을 실행하지 않고 PR 분리 안내를 한 번 게시해야 한다.
- 실행 중 다음 호출의 예약 비용이 잔여 비용을 초과한 경우, 시스템은 새 호출을 시작하지 않고 부분 리뷰를 게시하지 않아야 한다.
- 시스템은 모든 OpenAI 호출에 출력 토큰 상한을 적용해야 한다.
- 시스템은 API가 반환한 usage를 사용하여 uncached input, cached input, output 비용을 정수 단위로 누적해야 한다.
- PR branch의 설정은 조직이 정한 비용 상한, 허용 모델, 가격표 또는 호출 상한을 높이거나 비활성화할 수 없어야 한다.
- 시스템은 prompt, diff, tool 결과, API key 또는 원문 모델 응답을 비용 로그에 기록하지 않아야 한다.
- 시스템은 단일 리뷰와 병렬 리뷰에 동일한 GitHub 리뷰 body 및 판정 계약을 사용해야 한다.

## 성공 기준

- 단일 리뷰 경로와 병렬 리뷰 경로 모두 성공 시 GitHub POST 횟수가 1이다.
- 병렬 reviewer 수와 완료 순서가 달라도 통합 결과 순서와 판정이 동일하다.
- 분할 기준 초과 시 OpenAI 호출은 0회이고 분할 안내 POST는 1회이다.
- 비용 preflight 초과 시 OpenAI 호출은 0회이고 비용·분할 안내 POST는 1회이다.
- 병렬 호출 예약 합계와 확정 비용의 합은 설정된 공유 상한을 넘겨 새 호출을 예약하지 않는다.
- 사용자 리뷰 본문에는 single, multi, shard, agent 같은 내부 실행 정보가 표시되지 않는다.
