# Multi-Agent PR Review 요구사항

## 목적

큰 PR도 정확하게 리뷰하되, 사용자에게는 통합 리뷰 하나만 제공한다. 리뷰 비용과 처리 가능한 PR 크기를 제한한다.

## 동작

| 조건 | 처리 |
|---|---|
| 작은 PR | 단일 리뷰 |
| 큰 PR | 내부 병렬 리뷰 후 결과 하나로 통합 |
| 허용 상한 초과 | 리뷰하지 않고 PR 분리 요청 |
| 비용 상한 초과 | 부분 리뷰 없이 PR 분리 요청 |
| 시스템 장애 | 코드 결함과 구분된 리뷰 실패로 표시하고 재실행 안내 |

## 기본 기준

- 단일 리뷰: 최대 1,200 가중 라인 / 40파일 / 40k tokens
- 병렬 리뷰: 최대 2,500 가중 라인 / 80파일 / 100k tokens
- 병렬 reviewer: 최대 4개
- 비용: PR당 최대 $1
- 외부 GitHub 리뷰: 실행당 최대 1개

## 리뷰 항목

- 스펙 문서
- 스펙과 구현 정합성
- 기능 오류
- 보안
- 아키텍처
- API·DB 호환성
- 동시성·데이터 무결성
- 코드 품질
- 테스트 정합성
- 이전 리뷰 해결 여부

## 예외

- generated/vendor/lock 파일은 설정에 등록된 경우만 제외한다.
- patch를 받지 못한 필수 파일이 있으면 PR 분리를 요청한다.
- 긴급 hotfix도 자동 승인하지 않는다.
- LLM 또는 GitHub 장애는 코드 결함과 구분한다.
- 부분 리뷰 결과는 게시하지 않는다.

## 안전 불변식

- 시스템은 저장소의 base commit에 있는 리뷰 설정을 적용해야 한다.
- GitHub가 반환한 patch의 변경 줄 수가 파일 inventory와 다르면, 시스템은 불완전 diff로 처리해야 한다.
- binary 변경이 포함되면, 시스템은 해당 파일을 리뷰 대상과 크기 계산에서 제외해야 한다.
- 순수 rename 발생 시, 시스템은 이전 경로와 새 경로를 coverage와 리뷰 입력에 포함해야 한다.
- 병렬 리뷰가 활성화된 경우, 시스템은 모든 reviewer에게 전체 파일 manifest를 제공해야 한다.
- 병렬 리뷰가 활성화된 경우, 시스템은 공유 context 비용을 각 shard 한도에 포함해야 한다.
- tool 사용이 불가능한 경우에도, 시스템은 전역 reviewer에게 변경 patch 근거를 제공해야 한다.
- 합성 결과 생성 시, 시스템은 finding과 이전 리뷰 해결 내역을 추가·삭제·변조하지 않아야 한다.
- 리뷰 게시 시, 시스템은 검토한 head SHA를 `commit_id`로 지정해야 한다.
- 동일한 head SHA 리뷰가 다시 실행되면, 시스템은 GitHub Actions bot이 게시한 기존 결과를 중복 게시하지 않아야 한다.
- 저장소 설정 조회가 404 이외의 이유로 실패하면, 시스템은 기본 설정으로 진행하지 않고 인프라 오류로 종료해야 한다.

## 성공 기준

- 단일·병렬 모두 리뷰 하나만 게시한다.
- 누락된 파일 없이 전체 변경을 검토한다.
- PR당 비용을 $1 이하로 제한한다.
- 상한 초과 시 LLM 호출 없이 분리를 안내한다.
- 내부 agent 정보는 리뷰 본문에 노출하지 않는다.
