# 분할 리뷰 출력 계약과 오류 진단

## 배경

- 사용자 요청: SR-AMR-Base Actions 실행 `34231443106`의 오류를 테스트하고 수정한다.
- 실행 당시 봇 `638ea62`는 14개 변경 파일을 두 shard와 global 검토로 분할했다.
- 공통 시스템 프롬프트는 ReviewResult 출력을 요구하지만 분할 분석은 ReviewPartial을 검사한다.
- CLI는 RESPONSE_SCHEMA_ERROR 분류만 기록하여 파싱 실패와 범위·병합 검증 실패를 구별할 수 없다.
- 실제 AI 응답이 보존되지 않아 과거 실행의 정확한 실패 분기를 확정할 수 없다. 테스트는 확인된 계약 충돌과 진단 누락을 재현한다.

## 요구사항 (EARS)

- MCD-01: 분할 리뷰 분석이 실행되는 동안, 시스템은 shard와 global 분석의 시스템 프롬프트와 API 응답 스키마에 ReviewPartial 출력 계약을 사용해야 한다.
- MCD-02: 단일 리뷰 또는 최종 병합이 실행되는 동안, 시스템은 ReviewResult 출력 계약을 유지해야 한다.
- MCD-03: 담당 파일 외 참고 문서가 분석 입력에 포함되는 경우, 시스템은 담당 파일과 참고 파일의 역할 및 finding 허용 범위를 프롬프트에 명시해야 한다.
- MCD-03a: 공유 문서가 해당 shard의 담당 파일인 경우, 시스템은 해당 문서를 finding 등록이 금지된 참고 파일 목록에서 제외해야 한다.
- MCD-04: 리뷰 인프라 오류 발생 시, 시스템은 오류 분류와 안전한 실패 사유를 실행 로그와 Actions 요약에 기록해야 한다.
- MCD-05: 파이프라인 분석 또는 병합에서 리뷰 인프라 오류 발생 시, 시스템은 실행 단계와 해당 분석의 예정된 unit ID를 오류 진단에 포함해야 한다.
- MCD-06: 오류 진단 기록 시, 시스템은 응답 원문·예외 원인의 원문·인증 정보를 진단에 포함하지 않아야 한다.
- MCD-07: 응답 또는 범위·병합 검증 실패 발생 시, 시스템은 검증을 우회하거나 결과를 정상 판정으로 대체하지 않고 비정상 종료해야 한다.

## 성공 기준

- 수정 전 출력 계약 충돌과 사유 누락을 드러내는 테스트가 실패한다.
- 수정 후 shard/global 호출의 프롬프트와 response model 일치 및 단일·병합 동작을 테스트한다.
- 파싱, 범위 검증, 병합 실패에서 사유와 실행 문맥이 보존되며 민감한 원문은 출력되지 않는다.
- 관련 테스트 및 전체 로컬 테스트를 실행한다. 외부 AI 실행의 성공으로 과거 장애 원인을 확정하지 않는다.
